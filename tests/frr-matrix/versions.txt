# FRR versions tested by the FRR test matrix (one git tag per line).
#
# Tags are git tags of https://github.com/FRRouting/frr (frr-X.Y.Z). Used by
# build-frr-versions.sh when run without arguments and by `make frr-matrix`.
# The GitHub Actions workflow .github/workflows/frr-matrix.yml reads its
# matrix from this file too, so adding a line here is all it takes to test a
# new version.
#
# Line format: "TAG" or "TAG LIBYANG_REF". The optional second field is a
# libyang git tag (https://github.com/CESNET/libyang) that is built from
# source and used instead of the image's system libyang. FRR's configure only
# enforces a *minimum* libyang, but releases up to ~10.0 still call libyang-2
# APIs that were removed in libyang 3, so they need an explicit older libyang.
# Releases >= 10.1 build against the image's libyang 3.x and need no field.
#
# The libyang refs below are chosen so each release builds cleanly:
# frr-10.0.5 needs a libyang newer than its CI pin (it calls lyd_trim_xpath,
# added after v2.1.128), while frr-9.1.3 uses the v2.1.80 its own CI tested
# against. (Separately, frr-9.1.3's daemons reserve ~96 GB of virtual memory
# and cannot fork() during -d daemonization — run-tests.sh falls back to
# foreground mode for it. See README.md.)
#
# NOT listed (cannot build in the trixie-based image): frr-7.5.1 and
# frr-8.5.7. They predate libyang 2 and Python 3.13 — they need libyang 1.x
# and a Python that still exports Py_SetStandardStreamEncoding, i.e. a
# legacy (pre-2022) build environment. See README.md for details.
